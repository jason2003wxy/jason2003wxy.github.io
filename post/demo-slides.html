01 · The problem

Research compounds.
LLM sessions don't.

Without structure
  • Behaviour varies session to session
  • No quality guarantee on any output
  • Errors repeat — there is no correction memory
  • The model answers from training data when the wiki is the source of truth
  • Context window evicted the moment the session ends
With the CLAUDE.md architecture
  • Every session identical — same routing, same gates
  • Quality enforced at write time, by checklist
  • Errors captured → lessons → prevention rules
  • Hard rule: "no file in raw/ or page in wiki/ → do not answer"
  • Knowledge survives across sessions in wiki/ and the DB
The key insight The session is stateless, but the wiki is persistent — and CLAUDE.md makes the model behave as if it remembers everything it has ever ingested.
02 · The pattern

The Karpathy LLM Wiki loop

Three roles, one compounding artefact. The human curates; Claude maintains; the wiki accretes.

👤 Human — senior editor
  • Drops source files into raw/
  • Asks questions
  • Approves or corrects
  • Owns every synthesis decision
⚡ Claude Code — maintainer
  • Reads sources, extracts & structures
  • Maintains links + indexes
  • Queries the financial DB
  • Self-corrects via lessons.md
📁 wiki/ — the artefact
  • Interlinked markdown pages
  • Source-cited, quality-gated
  • Compounds across sessions
  • Queryable by the human
What makes this more than a basic LLM wiki An explicit, layered architecture that makes the model's behaviour deterministic and auditable — plus a second, structured data plane behind it.

04 · Knowledge-plane architecture

Three layers, one rule each

Every behaviour lives in exactly one layer. No layer defines what belongs to another.

Layer 1 — Constitution

CLAUDE.md

  • File-type routing (Step 0)
  • Immutable behavioural rules
  • Subagent strategy
  • Self-improvement loop
  • Points to the layers below
Layer 2 — Process

templates/workflow-*.md

  • Step-by-step ingest workflows
  • Pre-flight checks & gates
  • When to load which format file
  • Offer / confirmation points
  • Never defines output format
Layer 3 — Output spec

templates/format-*.md

  • Exact page structure
  • Pre-write checklists (S / C / SS / AS)
  • Conditional sections
  • Single source of truth for page content
Design principle CLAUDE.md orchestrates. Workflow files process. Format files define output.

10 · Getting better on its own

The self-improvement loop

The system improves without anyone re-engineering CLAUDE.md — corrections become permanent prevention rules.

## Self-Improvement Loop (CLAUDE.md)

Session start:
  BEFORE responding to the first message,
  read templates/lessons.md.
  Apply its prevention rules to all
  subsequent work in the session.

When the user corrects you:
  1. STOP. Do not start the fix yet.
  2. Append a log.md entry:
     ## [YYYY-MM-DD] correction | <summary>
  3. THEN fix the underlying issue.
  4. Write a structured lesson:
     Trigger / Root cause / Fix / Rule
An actual lessons.md entry 
## 2026-06-05 — Quality gate drift

Trigger:  the S-table in the workflow had
  drifted from the format file — three
  copies of one gate diverged.
Root cause: gate defined in the workflow,
  not the format file. Duplication → drift.
Fix: collapsed Step 9 to a pointer at the
  two format files.
Rule: any gate targeting page content lives
  in the format file. Extend once.

Lessons are a working ruleset, not an archive — superseded entries are pruned when new ones land.

11 · On top of the sources

The synthesis pipeline

Two workflows sit above the ingested source summaries — each consumes the layer below, never the raw files again.

Input layer

wiki/‹ticker›-‹period›.md
source summaries, one per report

wiki/‹company›.md
company page, updated each ingest

Consumed by both synthesis workflows.

workflow-signal-scan.md

Walks 72 universal signals (A/B/C/D/M classes) + the opportunity arm (Munger 4-patterns, §7 拐点).

Loads signal-applicability-matrix.md — no per-test re-derivation. Fetches raw files conditionally, per signal.

→ wiki/‹company›-财报信号.md

workflow-assessment.md

Consumes the signal scan — does not re-read raw.

Renders 5 verdicts: 真实盈利 · 可持续 · 能&愿分享 · 估值 · 反向机会. Thresholds live in format-assessment.md.

→ wiki/‹company›-评估.md

Chain rule Assessment cannot run without a signal scan; a signal scan cannot run without ≥1 source summary. The dependency is enforced by pre-flight checks.
12 · Why it's built this way

Key design decisions

01 · Format files own the gates

The gate is loaded with the output spec at write time, so it can never drift from what it checks.

02 · DB is the statement source new

Step 3.6 pulls P&L / CF / BS from db_fin_query; they are never hand-typed. Currency is verified at 3.6a before use.

03 · Subagent parallelism is explicit

CLAUDE.md names exactly when to fan out (batch ≥2 reports, HK checks, lint) and when not to (single ingest, single read).

04 · Synthesis is user-triggered

Steps 11–12 are offers. The model never auto-rebuilds a scan or assessment over valid verdicts.

05 · Source authority is absolute

raw/ is immutable (the DB is the one maintained exception). No training-data answers when a source exists; no fabrication when it doesn't.

06 · A correction writes twice

A log.md line (what happened) and a lessons.md rule (how to prevent it). Neither substitutes for the other.

13 · The system governs its own code new

Coding discipline is a layer too

The ETL and query scripts in analysis/ are held to the same explicit standard as the prose. coding.md loads whenever Python or R is written, modified, reviewed, or tested.

Loaded for

Any code task in analysis/, tools/, or anywhere else — skipped only for read-only exploration.

yahoo_to_key_var.py mantain_wiki_db.py db_fin_query.py
Think before coding

State assumptions. Surface tradeoffs. Stop when confused — name what's unclear rather than guess.

Simplicity first

Minimum code that solves the problem. No speculative flexibility. 200 lines that could be 50 → rewrite.

Surgical changes

Touch only what the task needs. Match the surrounding code. No drive-by refactors.

Worked patterns

coding_EXAMPLES.md pairs each rule with a concrete before/after from this repo.
