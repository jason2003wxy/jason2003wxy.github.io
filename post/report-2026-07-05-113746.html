Where Things Go Wrong

Your main friction comes from subagents lacking the permissions they need, buggy DB code that doesn't generalize across accounting standards, and Claude misjudging the scope or format of your requests before you correct it.

Subagent permission failures
Your parallel subagents repeatedly hit Bash and write permission blocks, forcing the main agent to run queries or write files directly and clean up after failed runs. You could preauthorize the specific Bash/Write permissions your ingestion agents need up front so fan-out workflows complete without manual salvage.
  • All 3 spawned agents hit Bash permission blocks querying SQLite, so Claude had to run queries directly and feed results back manually, negating the parallelism benefit.
  • Subagents lacked write permissions and created 0-byte placeholders or duplicate pages, requiring manual cleanup plus 3 pages needing manual index/log entries.
DB code not generalizing across accounting standards
Python query code built for A-share (CAS) accounts silently broke on H-share (IFRS) filings, returning wrong or missing line items. Flagging the accounting standard explicitly at ingestion time and adding IFRS-aware branches would prevent these thin or incorrect wiki pages.
  • Python DB query code built for A-share CAS accounts failed on H-share IFRS company 00552, returning wrong or missing values for key line items.
  • CF direct-method items were mostly empty for 00552 and the Taxes Refund Paid subtotal was misplaced under inflow, requiring a restructure of the CF rows.
Misjudged request scope and format
Claude sometimes assumed the wrong output format, skipped cross-reference checks, or claimed a file was already handled, forcing you to redirect it. Stating the exact deliverable format and cross-check expectations in your initial prompt would reduce these correction loops.
  • You asked for a LinkedIn connection note but Claude drafted a full thank-you letter, requiring you to clarify and have it redo the concise version.
  • Claude failed to check wiki/index.md for cross-references before updating a company page, and you had to point out the gap before it grepped all references and corrected.

Custom Skills
Reusable /command prompts defined as markdown files for repetitive workflows.
Why for you: Your B1–B5 ingestion workflow (create wiki page, update index, add log entry, check cross-references) runs dozens of times — a /ingest skill would encode all the steps you keep re-explaining.
Create .claude/skills/ingest/SKILL.md: --- name: ingest --- For each file in raw/: route through Step 0, apply the correct B-level workflow, create/update the wiki page, grep index.md for cross-references, update wiki/index.md, and append a log entry. Verify no 0-byte or duplicate pages were created.
Hooks
Shell commands that auto-run at lifecycle events like after edits.
Why for you: You repeatedly forget index/log updates and hit exact-match edit failures; a post-edit hook could auto-check that every new wiki page has an index entry.
In .claude/settings.json: { "hooks": { "PostToolUse": [{ "matcher": "Write|Edit", "command": "grep -q \"$(basename $CLAUDE_FILE .md)\" wiki/index.md || echo 'WARN: page not in index.md'" }] } }
